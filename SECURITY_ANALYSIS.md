# Анализ безопасности API Calculator

## 1. Цель анализа

Цель этапа — выполнить автоматический анализ безопасности учебного API Calculator и определить проблемы в исходном коде, CI-конфигурации и Docker-образе.

На момент анализа имеются результаты двух инструментов:

- Semgrep — статический анализ исходного кода и конфигурации;
- Trivy — анализ Docker-образа и зависимостей на известные уязвимости.

## 2. Результаты Semgrep

Semgrep выполнил анализ 8 файлов проекта.

Результаты:

- Rules run: 329;
- Targets scanned: 8;
- Findings: 6;
- Blocking findings: 6.

### 2.1 Изменяемые теги GitHub Actions

Semgrep обнаружил несколько ссылок на GitHub Actions, закреплённых только по тегу версии:

```yaml
uses: actions/checkout@v4
uses: actions/setup-python@v5
uses: aquasecurity/trivy-action@v0.36.0
```

Всего к этой категории относятся 5 из 6 замечаний.

Проблема заключается в том, что тег версии является изменяемой ссылкой. Владелец Action может переназначить тег на другой commit, поэтому с точки зрения безопасности цепочки поставки надёжнее использовать полный 40-символьный commit SHA.

Пример рекомендуемого варианта:

```yaml
uses: actions/checkout@<FULL_COMMIT_SHA>
```

### 2.2 Отсутствие непривилегированного пользователя в Dockerfile

Semgrep также обнаружил отсутствие инструкции `USER` в Dockerfile.

При отсутствии отдельного пользователя процесс приложения может запускаться внутри контейнера от root.

Это повышает потенциальные последствия компрометации приложения.

Рекомендуется создать отдельного пользователя и запускать приложение от его имени.

Пример:

```dockerfile
RUN useradd -m -u 10001 appuser
USER appuser
```

## 5. Предлагаемые меры

Для повышения безопасности проекта рекомендуется:

1. Закрепить внешние GitHub Actions на конкретные commit SHA.
2. Добавить непривилегированного пользователя в Dockerfile.
3. Обновить `msgpack` минимум до версии `1.2.1`.
4. Обновить `setuptools` минимум до версии `78.1.1`.
5. Обновить `urllib3` минимум до версии `2.8.0`.
6. Регулярно обновлять базовый Docker-образ.
7. Повторно запускать Semgrep и Trivy после внесения изменений.

## 6. Итог

Проведённый анализ показал, что проект успешно проверяется Semgrep и Trivy.

Критических уязвимостей Trivy не обнаружил, однако выявлены четыре уязвимости уровня HIGH в Python-зависимостях.

Semgrep обнаружил шесть замечаний, основные из которых связаны с безопасностью внешних GitHub Actions и запуском контейнера без отдельного непривилегированного пользователя.

После обновления зависимостей, настройки пользователя контейнера и закрепления GitHub Actions по commit SHA рекомендуется выполнить повторный запуск pipeline и сравнить результаты.
